# Doctoral Funnel App

Doctoral Funnel App is a browser-based research design coach that helps doctoral students move from a broad interest to a defensible research question through a six-stage inverted funnel.

## Features

- Animated inverted funnel navigation
- Accessible spoken prompts with mute, replay, and stop controls
- Optional browser voice answers where speech recognition is supported
- Typed answers with adaptive question starters
- Logic analysis for specificity, coherence, evidence discipline, construct alignment, measurability, gap validity, and methodological feasibility
- Revision and backtracking across all six stages
- Browser save/resume through local storage
- JSON project import/export
- Markdown research blueprint export
- Optional AI-in-HR dissertation starter example
- Verification warnings for claims that need scholarly sources
- Stage-specific question/claim planning and MEAL (Main claim, Evidence, Analysis, Link) drafting
- Source synthesis matrix with themes, methods, findings, limitations, counterevidence, and reading status
- Planning and source matrix included in saved projects and blueprint exports

## Six Funnel Stages

1. Broad research domain
2. Research context
3. Specific research problem
4. Scholarly evidence
5. Research gap
6. Defensible doctoral research question

## Natural Narration Setup

Marin AI narration is prepared but requires a connected private server and a funded OpenAI API account. Without `VITE_NARRATION_URL`, the app explicitly shows Marin as awaiting connection and continues to use browser speech. This does not inherit or identify your ChatGPT voice.

The private service uses Node.js 22 or later and needs no extra packages. Set `OPENAI_API_KEY` in your hosting provider's secret/environment settings, never in GitHub, chat, a frontend variable, or a published file. Configure `ALLOWED_ORIGINS` for the exact app origin. Run `npm run narration`; the default binds to loopback for local development. A hosted service needs `HOST=0.0.0.0` and an HTTPS endpoint supplied by its host. Configure `VITE_NARRATION_URL=https://YOUR-SERVICE/speech` when building the frontend, then publish that build to GitHub Pages.

For local development, use `VITE_NARRATION_URL=http://127.0.0.1:8787/speech` with the local app. Environment variables must actually be loaded into the process; `.env.example` documents the settings but is not loaded automatically by the Node server. Node's `--env-file` option or your host's secret settings can supply them.

The API service accepts only six preset stage IDs. It never receives project answers, citations, or user-authored research text. Marin reads the stage introduction and main question; personalized coaching remains visible on screen. Browser narration retains its existing spoken coaching. Mute, stop, backtracking, replay, and pace controls apply to both modes. Audio is labeled AI-generated. If Marin is unavailable, the app clearly announces browser fallback; autoplay restrictions require a replay click.

Audio is cached in service memory and in the current browser session. Each server process allows at most 12 generation attempts and 120 requests per minute. These are abuse/spend safeguards, not authentication: CORS does not stop non-browser clients. Before public hosting, set account spending controls and host-level rate limits. Restarts and multiple server instances reset/multiply in-memory limits and caches. API charges and hosting charges are separate from ChatGPT subscription usage.

Speech implementation basis: https://developers.openai.com/api/docs/guides/text-to-speech

## Academic Caution

The app gives structured reasoning feedback. It does not verify literature claims. Any scholarly evidence or research gap should be checked against current peer-reviewed sources before being used in a dissertation proposal.

Scores are heuristic structural signals, not validated measures of research quality or committee readiness. Citations and reading checkboxes do not remove verification flags.

## Resource Basis

Planning tools were informed by National University's synthesis and analysis guides at https://resources.nu.edu/researchtools/synthesisandanalysis and https://resources.nu.edu/researchtools/synthesishowto, together with the user's doctoral literature review workshop notes. The workshop notes were AI-generated summaries, not a verified transcript. No workshop example statistics or example citations are presented as empirical evidence. Private source documents are not included in this public repository.

The six-stage research-design funnel remains distinct from the workshop's literature-review outline. Planning can explore a proposed contribution, but does not presume the study's findings or solution.
